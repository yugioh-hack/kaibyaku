# カード詳細画面からの切り抜き 設計

作成日: 2026-11-03。対象は `main`（2.1.1）。

## 目的

デッキ編集などで開くカード詳細画面（左にカード、右に名前・ステータス・テキストの欄）のスクリーンショットからも、カードを切り抜いて保存する。

- 拡大画面と詳細画面が混ざった入力でも、判定と保存が壊れない。
- 詳細画面のカードは拡大画面のちょうど2/3の大きさ（高さ1440の画面で、拡大画面は1302px、詳細画面は869px）。保存したファイルで見分けられるようにする。既定では `detail/` フォルダに分ける。

## 調べたこと

使った画像は `マイドライブ/MD/mdript-sample2-img/` の35枚（すべて2560x1440のJPEG）。拡大画面が33枚、詳細画面が1枚（`20261022201122_1.jpg`）、デッキ編集画面が1枚（`20260524233102_1.jpg`）。詳細画面の1枚は、その後 `mdript-sample3-img/` に移したので、今の sample2 は34枚。

### 拡大画面は詳細画面の上に重なっている

拡大画面は詳細画面の上に重ねて表示される。背景には暗くなった詳細画面が残り、左には同じカードがある。

詳細画面の位置 `[175, 220, 771, 1089]` で33枚の拡大画面を照合すると、33枚とも拡大画面と同じカードIDになり、距離は4〜22だった（拡大画面の位置とほぼ同じ）。**詳細画面の位置で一致したかどうかでは、2つの画面を見分けられない。** 照合の順序や距離では決めず、中央に大きいカードがあるかどうかで決める。

### 中央に大きいカードがあるかは `on_edges` で分かる

拡大画面の予測位置（`predict_card_box`）で `on_edges` を調べた結果:

| 画像 | 拡大画面の位置 | 詳細画面の位置 |
| --- | --- | --- |
| 拡大画面 33枚 | すべて真 | すべて真（背景のカード） |
| 詳細画面（元画像と、チャットに貼った縮小版） | 偽 | 真 |
| デッキ編集画面 | 偽 | 真（左の欄の枠） |

### 詳細画面の位置と照合の結果

外枠まで含めた `[175, 220, 771, 1089]`（2560x1440）で切り抜くと、カードの外枠がちょうど収まる。内側の枠（`[198, 242, 750, 1046]`）では距離が20〜26に悪化するので、外枠を使う。

| 画像 | 位置 | 結果 |
| --- | --- | --- |
| 詳細画面 2560x1440（元画像） | `[175, 220, 771, 1089]` | `4370` 確定、距離12、2位との差26 |
| 上の画像を1920x1080に縮小 | 比で計算 | `4370` 確定、距離12 |
| 1280x720に縮小 | 比で計算 | `4370` 確定、距離14 |
| 3840x2160に拡大 | 比で計算 | `4370` 確定、距離12 |
| 同じカードの拡大画面（`20261022201114_1.jpg`） | 拡大画面の位置 | `4370` 確定、距離12 |
| デッキ編集画面 | 詳細画面の位置 | 距離40（カードなしのまま） |

距離は拡大画面と変わらないので、確定の基準は変えなくてよい。

今の処理では、詳細画面は「カードなし」（距離38）になる。中央の拡大画面の位置で、右の説明欄を照合しているため。

### 種類と言語を混ぜた詳細画面20枚

`マイドライブ/MD/mdript-sample3-img/` の20枚（すべて2560x1440のJPEG、詳細画面。上の `20261022201122_1.jpg` を含む）。日本語13枚・英語7枚。このフォルダには検証の後に画像が足され、今は54枚ある。足した画像は確かめていない。通常・効果・儀式・融合・シンクロ・エクシーズ・リンク・ペンデュラム（日英とも）・魔法（永続・速攻）・罠を含む。パック画面から開いた詳細画面（左右に矢印がある画面）も2枚ある。

詳細画面の位置 `[175, 220, 771, 1089]` で処理した結果（名前は公式DBから取得したカード名で確認）:

| | 結果 |
| --- | --- |
| 確定 | 20枚すべて。カード名はすべて画像のカードと一致 |
| 距離 | 0〜18（日本語0〜16、英語4〜18） |
| 2位との差 | 22〜42 |
| `on_edges`（詳細画面の位置） | すべて真なので、推定扱いにならず「距離32以下・差4以上」で確定する |
| `on_edges`（拡大画面の位置） | すべて偽 |
| 英語判定 | すべて正しい。`stroke_ratio` は日本語0.97〜1.24、英語0.57〜0.63（基準は0.75以下で英語版） |
| 外枠の取り違え | 儀式の「カオス・ソルジャー」は `frame_twin` で `4370` になった |

近くの位置を4pxずつずらして試すと、`[179, 224, 770, 1085]` 付近で距離が2〜6下がる画像が多い。今の位置で全部確定するので、定数は変えない。ずれは微調整（`nudged`）で吸収できる。

今の処理（`identify(Auto)`）では、20枚とも中央の位置で照合し、19枚が距離34〜42の別のカード、1枚（`20261103180135_1.jpg`）は距離18で正しいカード（確定できず）になる。距離34や36の画像は、今は「要確認」として別のカード名で `review/` に保存されている。新しい流れでは、中央に枠がないので詳細画面の判定に進み、正しいカードで確定する。

## カードの位置

`predict_card_box` と同じく、高さ1440を基準にした比で計算する。横は画面中央からのずれで表す。

| | 上端 | 高さ | 幅 | 左端 |
| --- | --- | --- | --- | --- |
| 拡大画面（既存） | 69 | 1302 | 894 | 中央 − 447 |
| 詳細画面（新規） | 220 | 869 | 596 | 中央 − 1105 |

core に `predict_detail_box(w, h) -> [i64; 4]` を追加する。丸めは `predict_card_box` と同じ `round_ties_even`。`predict_detail_box(2560, 1440) == [175, 220, 771, 1089]`。

## 判定の流れ

`identify` の今の流れ（画像全体 → 拡大画面の予測位置 → 枠の検出 → 微調整）は変えず、その後に詳細画面の判定を足す。

```text
best = 今の identify の結果
if best が確定           → 拡大画面として返す（今と同じ）
if resolution が Box/Card → 返す（今と同じ）
if on_edges(拡大画面の予測位置) → 拡大画面として返す（今と同じ。背景の詳細画面は見ない）
detail = 詳細画面の予測位置を評価（枠が on_edges で合えば trusted）
         確定しなければ、詳細画面の予測位置を中心に nudged で微調整（今の微調整と同じ2段階）
return better(detail, best)
```

- 拡大画面の画像は、確定するか、`on_edges` が真で返るので、結果も処理時間も今と変わらない。確定しない拡大画面（要確認）でも、背景の暗いカードを詳細画面として保存することはない。
- 詳細画面の判定が走るのは、今「カードなし」か、中央に枠がない要確認の画像だけ。
- `Resolution::Fixed`／`Original` でも、詳細画面の予測位置を同じ順で試す（`Original(w, h)` は元の大きさで計算した位置を縮尺する）。
- 詳細画面の候補で `on_edges` が偽のときは、今の拡大画面の候補と同じく推定扱い（`estimated`）にする。

### 画面の種類

結果に画面の種類を持たせる。

```rust
pub enum Screen { Maximized, Detail }
```

`Found` に `screen` を足し、詳細画面の判定（予測位置・微調整）で得た候補を `Detail`、それ以外を `Maximized` にする。画像全体がカードの場合（切り抜き済みの画像、`--card`）は `Maximized` で、今と同じ場所に保存する。

## 保存

### 保存先

新しい設定 `detail`（コマンドライン版は `--detail folder|suffix`）。

| 値 | 動作 |
| --- | --- |
| `folder`（既定） | 詳細画面のカードを `出力先/detail/` 以下に保存 |
| `suffix` | 拡大画面と同じフォルダに、名前の最後に `_detail` を付けて保存 |

`folder` では、`detail/` を出力先の代わりの根として、今の規則をそのまま当てる。

```text
出力先/
├─ ブラック・マジシャン.webp
├─ review/
├─ en/
├─ not_card/
└─ detail/
   ├─ カオス・ソルジャー.webp
   ├─ review/
   └─ en/        # 言語でフォルダを分ける設定のとき
```

- `not_card/` は今どおり1か所にまとめる（照合できない画像は画面の種類も当てにならないため）。
- `suffix` では、`_en` などを付けた後に `_detail` を付ける（`カオス・ソルジャー_en_detail.webp`）。

### 重複の判定

`Saver::reserve` は、同じ保存先・同じ名前（`_altN` を含む）の既存ファイルとだけイラストを比べる。どちらの値でも、詳細画面のカードは拡大画面のカードと名前か場所が違うので、互いに「同じイラスト」としてスキップされない。大きい画像が小さい画像に押しのけられることはない。

詳細画面どうし、拡大画面どうしの重複スキップは今のまま働く。

### 結果とログ

- 結果のJSONに `"screen": "maximized" | "detail"` を足す（カードが見つからないときは `null`）。`types.ts` にも足す。
- `log.csv` の列は増やさない（追記形式で、既存のログと列がずれるため）。保存先のパスで見分けられる。
- 画面には新しい表示を足さない。保存先のパスと、行を選んだときの画像で分かる。

## 登録（照合データへの追加）

`identify_trusted`（登録で使う）は、候補のうち最初に評価できた位置を使う。詳細画面の画像では拡大画面の位置（右の説明欄）のハッシュを登録してしまう。

`identify_trusted` は次の順で位置を決める。

1. 今の候補（画像全体、拡大画面の予測位置）で、今と同じく最初に評価できた位置。ただし拡大画面の予測位置は `on_edges` が真のときだけ使う。
2. 1がなく、詳細画面の予測位置で `on_edges` が真なら、その位置。
3. どれもなければ、今と同じく拡大画面の予測位置。

拡大画面の33枚はすべて1で今と同じ位置になる。テストで確かめる。

登録できなかったときのメッセージ「カードの拡大画面を全画面で撮った画像を使ってください」は「カードの拡大画面か詳細画面を…」に直す。`prepare` の備考「カードの拡大画面ではないようです」も同じく直す。

## テスト

core:

- `predict_detail_box(2560, 1440) == [175, 220, 771, 1089]`。
- 合成画像: 詳細画面の予測位置に枠と模様を置き、その位置のハッシュだけを持つ照合データで `identify(Auto)` が確定し、`screen` が `Detail` になる（`identify.rs` の既存テストと同じ作り方）。
- 合成画像: 拡大画面と詳細画面の両方の位置に同じ模様を置く（拡大画面の重なりを再現）。拡大画面の位置で返り、`screen` が `Maximized` になる。拡大画面側を少し崩して要確認にしても、`on_edges` が真なら `Maximized` のまま。

cli:

- `detail = folder`: 確定は `detail/`、要確認は `detail/review/`、`split = en` の英語版は `detail/en/`、照合できないものは `not_card/`。
- `detail = suffix`: `_detail` が付き、`_en` の後ろに付く。
- 同じカードの拡大画面と詳細画面を同じ出力先に処理しても、どちらも保存され、「同じイラスト」でスキップされない（両方の値で）。
- `identify_trusted` が、拡大画面の画像では今と同じ位置を返し、詳細画面の画像では詳細画面の位置を返す。

既存の回帰（`python_golden`、`png16_golden`、`tools/regress.py` の256枚）が変わらないこと。

実画像（リポジトリには入れない。手元で確認する）:

- `mdript-sample2-img/` の34枚を処理し、拡大画面33枚は今と同じカードID・距離・保存先、デッキ編集画面は「カードなし」のまま。
- `20261022201122_1.jpg` は `detail/` に `4370` で確定する。
- `mdript-sample3-img/` の詳細画面20枚がすべて `detail/` に確定し、英語7枚は英語名で保存される（`split = en` なら `detail/en/`）。上の表と同じカード名になること。
- 詳細画面の画像を1920x1080・1280x720に縮小しても確定する。
- 両方のフォルダを1回で処理しても、拡大画面と詳細画面の同じカード（カオス・ソルジャー）がどちらも保存される。

## 決めていないこと

- 16:9 以外の画面での詳細画面の位置。拡大画面と同じく、枠の検出と微調整に頼る。
